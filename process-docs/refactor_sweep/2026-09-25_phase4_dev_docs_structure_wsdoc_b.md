Fixture gotchas:
- The 429 failure mode is a sliding window (limit plus window seconds, lazily pruned request timestamps under the same state lock), replacing an absolute counter that could not tell a well-paced caller from a badly-paced one (both sent N total requests and tripped it identically with no way back).
- Route table and state are module-level globals: one fixture server per process. A second start overwrites routes/state while the first keeps serving on its port against the second's table. Use separate processes for isolation.
- The robots-empty-404 path is a genuine empty-body 404. A plain 404 with a real body does not read as failed fetch to crawl4ai (success is bool(html), set before anti-bot checks; confirmed in async_webcrawler and antibot_detector). Currently inert because discovery no longer fetches discovered URLs; kept for the scrape step.
- The thin-body page shape (an empty app div, no p/h1/etc.) is deliberate: the anti-bot structural check needs two signals on pages under 5000 bytes (no visible text and none of p, h1-6, article, section, li, td, a, pre). All other pages carry a real h1 and p sentence so they never trip the check.
- The RSC demo page and its two children are deliberately not linked from the main graph and not counted in ground-truth total URLs; they exist so the navtree feeder can be called directly against the RSC push shape. Do not link them in.
- Orphan chain, revisit page, and version-dup page were removed together with their tests when the browser-driven link-graph traversal was removed. The navtree-v1-only pages stay: they test the feeder's own version union.

Resume-state probe gotchas (observed):
- Each of the four experiments cancels its BFS from inside its state-change callback after the single seed's first level; discovered next-level URLs are inspected via the captured state, never fetched. Results lists therefore hold only injected seeds.
- An empty resume_state dict is falsy: the strategy silently crawls the start URL normally (experiment 2c).
- A wrong key in a non-empty resume_state (seed_urls instead of pending) enters resume mode, finds nothing, never uses the start URL, and yields zero results without error (experiment 2b).
- Experiment 3 reads the children count through a chained get with zero defaults, with no assertion that a state was captured; against a failing seed fetch it would report 0 for the wrong reason. The callback fires whenever result.success is true, and both variants' seed fetches did succeed, so the 0 for variant A is genuine.

## coindesk_proxy_riding (moved out of DOCS.md)

- Architecture: B Playwright browser processes (default 1) and N concurrent rider tasks (default 20), slot i mapped to browser i mod B. Each task pulls raw proxies directly from the pool (no pre-validation). Every fetch uses a run config with a proxy config, giving a fresh Playwright context per proxy through crawl4ai's config-signature mechanism plus a session id and kill_session (fresh cookies per URL, browser stays alive). Regwall detection runs on the result's raw markdown, not raw HTML, because the regwall signal strings are hidden React components always present in the HTML. A proxy is burned and rotated when cumulative regwall hits reach the burn threshold.
- Self-contained: the pool module is a local copy because a hookify rule blocks src imports in dev scripts. Test modules import the src riding package lazily inside function bodies.
- The riding module re-exports the run state, watchdog, abort, and fail-threshold names so the reporter can still resolve them from there. ## news_pipeline/theblock/acquire_pipe (moved out of DOCS.md)

Fetch primitive: curl_cffi Session with chrome impersonation; status values ok (valid content), dead (origin 404/410, proxy confirmed working; classified before the marker check), fail (connection error, timeout, CF block, or non-200 other than 404/410, or 200 with wrong content type).

Cooldown: in-memory, starts empty per process (per-job clean slate, no cross-job inheritance, no file I/O). A proxy is eligible again 60 minutes after burning; the manager also exposes the earliest next eligibility moment (used for the loop's wait-on-exhaustion), the eligible-candidates filter (pool order preserved), and a cooldown count.

Target: theblock index parsed into 64 sub-sitemap loc URLs. Direct httpx GET first; proxy rotation on a non-XML response (403, CF challenge); a network error raised by the direct GET propagates. The pool is caller-supplied. The home IP is CF-blocked for direct theblock GETs (403), which the proxy fallback handles.

Sustained loop:
- Startup calls the pool provider once and builds the active buffer; every 3600 s it calls the provider again and rebuilds (two pool-fetch sites, each recorded in the log as a pool refresh). On exhaustion (buffer and working set empty) it sleeps until the earlier of the next cooldown expiry and the next 60-minute tick, then rebuilds from the existing pool (no provider call, no refresh-timer reset). The sleep is a module attribute patchable in tests.
- Fetch result branches: ok records via the optional content handler (called at the ok branch, guarded by the batch-done set so only the first successful racer per URL records), appends to done, keeps the proxy in the working set, resets its consecutive-fail counter. dead appends to dead, preserves the proxy, does not burn or re-queue. fail adds to the batch-failed set with the two-strikes lifecycle: 2 consecutive fails burn the proxy (mark burned, remove from buffer and working set); a success resets the counter, so one transient fail never burns. Failed URLs go to the BACK of the queue to avoid hammering one URL with dead proxies. After the loop, only URLs not in the batch-done set are re-queued, removing the fail-before-success ordering hazard.
- Tail race: when pending URLs are fewer than free proxy slots, surplus proxies race the same remaining URLs round-robin (working set first, skipping already assigned); the first success wins; only the distinct-URL count is popped from the queue.
- The race loop variant (dead code on 2026-09-25) pulls URL and proxy pairs per worker, shuffles the pool once, consumes each proxy at most once (no cooldown, no burn, no refresh); gap is non-empty only if the pool ran out.

Buffer defaults: buffer size 1280, default concurrency 128. Build returns up to max size eligible proxies without any protocol sort; refill tops up immutably with set-membership dedup.

Logger: line-buffered JSONL, no in-memory counters; attempt records hold proxy key, timestamp, url, result; pool-refresh records hold event, size, timestamp. The stream must be closed before the janitor's end-of-job call. Log path acquire_pipe_logs/acquire_events_<ts>.jsonl.

Lock: fixed paths ~/.websearch-locks/acquire_pipe.flock (flock vessel) and acquire_pipe.lock (JSON sidecar with pid, job, target, started_at, status; job and target are metadata for the busy message only). Acquire flow: mkdir, stale cleanup (read pid, kill 0; ProcessLookupError unlinks the sidecar; PermissionError counts as held), open flock file, non-blocking exclusive lock; BlockingIOError raises a busy error carrying pid, job, and elapsed time; on success the sidecar is written atomically (mkstemp plus rename), and the finally block unlinks it and unlocks. SIGTERM kills Python before the finally block, leaving the sidecar; the kernel releases the flock and the next acquire recovers via stale cleanup.

Janitor: start wipes acquire_pipe_logs and acquire_pipe_reports contents. End reads the JSONL, computes stats (inter-hit deltas mean and median, total wall time max minus min ts, pool sizes from refresh events, t0 = min ts), writes a step plot cumulative_hits.png (x elapsed seconds, y cumulative ok, step post) via a lazily imported matplotlib (first call builds the font cache, about 1 s), writes a lean job.md with exactly 5 fields, unlinks the JSONL, and wipes the transient folders. Only acquire_pipe_jobs/<job_id>/ survives; do not inspect the log or report folders after a job completes.

Orchestrator: eager backfill pool load (about 22k proxies, always the full pool, no curated or pool flag) -> sitemap target from the same pool -> job id -> lock (busy error prints and exits 1) -> janitor start -> in-memory cooldown -> sustained loop with a pool-provider closure (eager pool on first call, re-fetch on the 60-minute tick) -> content handler persists raw XML and parses loc bytes -> dedup article URLs into theblock_article_urls.txt (tracked) -> dead count print -> logger close -> janitor end. Raw sub-sitemaps in acquire_pipe_output are gitignored. CLI: python acquire_pipe.py [--concurrency N] [--buffer_size N].
